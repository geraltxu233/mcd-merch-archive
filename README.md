# 麦门藏经阁

> 麦当劳中国周边藏品档案 ｜ 抢不到会遗憾，**不知道才最遗憾**。

一份能**一直查、能对比、能追溯**的麦当劳中国周边 / 联名藏品档案。数据来自麦当劳官方活动日历与积分商城，历史条目为人工补录并单独标注来源。

---

## 这是什么

麦当劳每年发售大量周边与联名藏品：联名棒球帽、限定徽章、毛绒玩具、联名球鞋、游戏机周边…… 但这些信息散落在活动页、积分商城和社交平台的碎片帖里，**看过就忘、过了就查不到**。

本项目把这类信息归拢成一份结构化档案：

- **每件藏品一张卡** —— 发售时间、获取方式、限量信息、原始文案快照
- **稀缺度榜** —— 按统一的稀缺度指数 SI 排序，可导出海报
- **获取路径指引** —— 在售/预热藏品标注官方操作路径（如「麦当劳 APP → 麦麦商城 → 积分兑换」），支持一键复制
- **全程可溯源** —— 每条记录标明是 MCP 自动采集还是人工补录

## 这不是什么

- ❌ 不是购物工具 —— 不提供下单、兑换、抽奖
- ❌ 不提供价格判断 —— **SI 是稀缺信号强度，不代表价格，也不代表升值潜力**
- ❌ 不提供库存查询 —— 官方接口无商品库存字段，无法回答"哪家店有货"
- ❌ 非麦当劳官方产品 —— 参赛作品，输出仅供参考

## 目标用户

| 用户 | 诉求 |
|------|------|
| 收藏向玩家 | 不遗漏、不重复、知道还差哪件 |
| 想入坑的新人 | 快速搞懂某件藏品是什么、还能不能拿 |
| 有积分的会员 | 了解积分兑换类藏品的门槛与历史 |
| 围观者 | 一眼看到最稀缺的几件 |

## 快速开始

### 1. 配置 MCP

本作品依赖麦当劳官方 MCP Server。先到 https://open.mcd.cn/mcp 申请 token，然后参照 `mcp-config.example.json` 配置（**只填环境变量，不要提交真实 token**）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

### 2. 环境

```bash
python --version        # 需要 3.10+
pip install Pillow      # 仅图片优化脚本需要
```

### 3. 使用

在支持 MCP 的对话环境中，让它调用 `campaign-calendar` 与 `mall-points-products`，
把返回结果存成 `data/采集快照/<日期>_<工具>.json`，然后：

```bash
python scripts/抽取入库.py --apply    # 抽取并合并入库（按 ext_key 去重，可重复执行）
python scripts/计算稀缺度.py           # 状态判定 + 稀缺度打分
python scripts/生成档案页.py           # 生成 视图/藏品档案.html
python scripts/校验藏品库.py           # 数据校验
```

打开 `视图/藏品档案.html` 即可查看图鉴与榜单，页面内可**一键导出榜单海报**。

也可以直接把这个仓库当作 **WorkBuddy Skill** 使用 —— 见 `SKILL.md`。

### 设计原则

1. **单一数据源** —— `data/藏品库.json` 是唯一数据源，图鉴、榜单等视图全部由它派生，视图不自存数据。
2. **事实与假设分离** —— 文档中所有推断显式标注，不编造数据。
3. **来源可溯** —— 每条记录标明 `mcp_calendar` / `mcp_mall` / `manual`，并保留原始文案快照。
4. **状态自判** —— 不使用 MCP 返回的 `status` 字段（实测不可信），按时间窗自行判定。

## 稀缺度指数（SI）

```
SI = (限量×0.30 + 门槛×0.20 + 窗口×0.20 + 售罄×0.20 + IP×0.10) × 20
```

五个维度各 0~5 分，加权求和后 ×20 得 0~100 分。算法公开、数据可溯源、结果可复现。

> **诚实声明**：SI 衡量的是「稀缺信号强度」，**不是价格，不是升值潜力**。权重为初版假设，后续可用社区讨论热度反向校准。
