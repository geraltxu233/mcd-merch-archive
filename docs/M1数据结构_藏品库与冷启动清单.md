# M1 数据结构：藏品库 Schema 与冷启动清单

> 版本：v1.0 ｜ 日期：2026-10-10 ｜ 前置：MVP 产品方案（方向二·藏品档案）
> 用途：M1 数据层的施工图。定义唯一数据源、字段、判定规则、计算公式与首批冷启动条目。
> 本文件所有推断标注【假设】；所有实测结论标注【事实】

---

## 一、设计原则

1. **单一数据源**：`data/藏品库.json` 是唯一数据源。图鉴、榜单等视图全部由脚本从它派生，**任何视图不得自存数据**。
2. **来源可溯**：每条记录必须能回答"这个字段从哪来"——MCP 采集标 `mcp_calendar` / `mcp_mall`，人工录入标 `manual`。
3. **原始快照留档**：MCP 文案会滚动消失【事实：历史不可回溯】，采集时必须把原始文案存进 `source_raw`，防止信息灭失。
4. **人机双读**：JSON 供脚本读写；同时提供"卡片模板"供人工补录时对照填写。

## 二、藏品库字段定义

| 字段 | 类型 | 必填 | 来源 | 说明 |
|------|------|------|------|------|
| `id` | string | 是 | 生成 | 唯一标识，见第三节规则 |
| `name` | string | 是 | MCP/人工 | 藏品名称 |
| `category` | enum | 是 | 人工 | 品类，见第四节 |
| `nature` | enum | 是 | 人工 | 性质，见第四节 |
| `ip_collab` | string | 否 | 文案解析 | 联名方，如 PEACEMINUSONE |
| `release_date` | date | 是 | MCP/人工 | 发售日期 YYYY-MM-DD |
| `acquire_method` | enum | 是 | MCP/人工 | 获取方式，见第四节 |
| `acquire_cost` | number | 否 | MCP | 加价购金额（元）或积分值 |
| `acquire_cost_unit` | enum | 否 | 推导 | `cny` / `points` |
| `acquisition_note` | string | 是 | 文案 | 获取规则原文，如"任意餐品消费 +39.9 元可得" |
| `limited_text` | string | 否 | 文案 | 限量表述原文 |
| `limited_count` | number | 否 | 解析 | 解析出的限量数量，解析失败留空 |
| `window_start` | datetime | 否 | MCP | 可获取起始时间 |
| `window_end` | datetime | 否 | MCP | 可获取截止时间 |
| `status` | enum | 是 | 计算 | 预热/在售/已结束/售罄，见第五节（**不由 MCP status 决定**） |
| `soldout_observed` | bool | 否 | 采样 | 是否由采集器观测到售罄（MCP status=3） |
| `image_url` | string | 否 | MCP | 图片直链 |
| `source` | enum | 是 | 系统 | `mcp_calendar` / `mcp_mall` / `manual` |
| `source_raw` | string | 否 | MCP | 原始文案快照（防信息灭失） |
| `si_score` | number | 否 | 计算 | 稀缺度指数 0~100，见第六节 |
| `si_breakdown` | object | 否 | 计算 | 五个维度的原始分，保证可复现 |
| `tags` | array | 否 | 人工 | 自由标签 |
| `first_seen` | date | 是 | 系统 | 首次入库日期（采集器写入） |
| `last_updated` | date | 是 | 系统 | 最后更新日期 |

## 三、ID 生成规则

```
格式：<release_date>-<category-slug>-<序号>
示例：2026-10-08-hat-01
```

- 同日同品类多件用两位序号区分。
- 一旦生成不再变更（视图与引用都依赖它）。

---

## 四、枚举值定义

| 字段 | 取值 |
|------|------|
| `category` | 帽子 / 徽章 / 丝巾 / 玩具 / 鞋袜 / 包袋 / 家居 / 摆件 / 游戏机 / 其他 |
| `nature` | 联名款 / 自有IP / 纪念款 / 联名潮玩 |
| `acquire_method` | 加价购 / 积分兑换 / 消费赠送 / 抽奖 / 买赠 |

---

## 五、status 判定规则（关键）

**不使用 MCP 返回的 status 字段**【事实：MCP status 大量造假，如 2026-03 到期的券仍标"上架"】。改为按时间窗自行判定：

```
当前时间 t
├─ t < window_start                          → 预热
├─ window_start ≤ t ≤ window_end
│    ├─ soldout_observed = true              → 售罄
│    └─ soldout_observed = false             → 在售
├─ t > window_end                            → 已结束
└─ window_start/window_end 缺失              → 未知（人工确认）
```

`售罄` 只能由采集器的多次采样观测得到，**不得推断**。

## 六、稀缺度指数（SI）计算公式

```
SI = ( 限量×0.30 + 门槛×0.20 + 窗口×0.20 + 售罄×0.20 + IP×0.10 ) × 20
```

各维度取值 0~5【假设：以下阈值为初版，待用社媒讨论热度反向校准】：

| 维度 | 5 分 | 4 分 | 3 分 | 2 分 | 1 分 |
|------|------|------|------|------|------|
| 限量 | 明确 <100 | <1000 | <10000 或"限量"无数字 | — | 无任何限量表述 |
| 门槛 | 加价购 ≥100元 / 积分 ≥5000 | 50~99元 / 1000~4999分 | 30~49元 / 500~999分 | <30元 / <500分 | 免费赠送 |
| 窗口 | ≤1 天 | 2~3 天 | 约 1 周 | 2~4 周 | >1 个月 |
| 售罄 | 确认售罄 | — | 已结束未确认售罄 | 在售 | 预热 |
| IP | 国际知名品牌联名 | 知名 IP（迪士尼等） | 艺人/潮牌 | 麦当劳自有 IP | 无联名 |

**诚实声明（必须随榜单展示）**：SI 衡量"稀缺信号强度"，**不是价格、不是升值潜力**。

## 八、MCP 字段 → 库字段映射（采集器用）

| 库字段 | 来源工具 | 来源字段/位置 |
|--------|---------|--------------|
| name | campaign-calendar / mall-points-products | 活动标题 / spuName |
| release_date | campaign-calendar / mall-points-products | 活动日期 / upTime |
| acquisition_note | campaign-calendar / mall-points-products | 活动内容介绍 / selling |
| window_start / window_end | mall-points-products | upTime / downTime |
| acquire_cost（积分） | mall-points-products | point |
| image_url | 两者 | 活动图片 / spuImage |
| source_raw | 两者 | 原文快照 |

**已知采集难点**【假设】：限量数字与加价购金额藏在自由文案里，需正则/NLP 抽取，可能不稳定 → M1 允许"半自动"（脚本抽取 + 人工确认）。

## 十、M1 交付物清单（下一步施工）

1. `data/藏品库.json` —— 按本 Schema 建立，先填第九节 12 条
2. `scripts/采集.py` —— 调 campaign-calendar + mall-points-products，抽取并合并进库（去重按 id）
3. `scripts/计算SI.py` —— 按第六节公式算分并写回
4. `data/采集快照/` —— 每次采集的原始 JSON 存档（防信息灭失）
5. 校验脚本 —— 检查必填字段非空、id 不重复、来源标注完整

## 十一、补充字段与流水线（2026-10-10 落地时新增）

### 新增字段 `ext_key`（稳定外部主键）

去重**不靠中文名、不靠 id**，靠 `ext_key`：

| 来源 | ext_key 格式 | 示例 |
|------|-------------|------|
| 活动日历 | `calendar:<活动日期>:<品类>` | `calendar:2026-10-08:帽子` |
| 积分商城 | `mall:<spuId>` | `mall:17694` |
| 人工补录 | `manual:<id>` | `manual:2025-09-30-toy-01` |

理由：中文名会变、id 会因顺序变化，ext_key 才是"同一件东西"的稳定标识。

### 采集流水线（实测跑通）

```
1. 采集  AI 调 MCP（campaign-calendar / mall-points-products）
        → 原始返回落 data/采集快照/日期_工具.json（防信息灭失）
2. 抽取  scripts/抽取入库.py 正则抽取（金额/限量/开售时间/品类）
        → 结果落 data/抽取候选.json 供人工确认
3. 补录  data/人工补录队列.json（人工写，带 source_raw 出处）
        → scripts/合并补录.py 并入
4. 算分  scripts/计算稀缺度.py（status 自判 + SI）
5. 出图  scripts/生成档案页.py（由库派生 HTML）
6. 校验  scripts/校验藏品库.py
```

**实测结论**：同批快照重跑 `--apply` 后"0 新增"，去重幂等成立；抽取器已能正确抽出加价购金额（39.9/68 元）、限量（5 份 / 150 份 / 11 万份）、开售时间。**已知抽取缺陷**：品类判定曾被文案里的对比词误伤（"丝巾搭配棒球帽"→误判为帽子），已改为"主产品行优先"规则修复。**结论：半自动抽取可行，但品类与命名仍需人工复核。**
