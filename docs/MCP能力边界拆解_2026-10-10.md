# 麦当劳 MCP 能力边界拆解

> 拆解日期：2026-10-10 ｜ 方法：33 个工具 Schema 全量阅读 + 6 个只读工具实测（标注【实测】处均为当日真实调用结果）
> MCP 接入方式：streamablehttp → https://mcp.mcd.cn，Bearer Token 认证（本地已配置）

## 〇、一句话结论

麦当劳 MCP 是一套"**点餐交易为主、情报查询为辅**"的能力集；对玩具情报站方向，**上新日历与积分商城两条查询链完整可用**，但原方向定义中的"附近哪家店有货"**没有工具支撑**（门店接口无玩具库存字段），必须降级为"开售时间提醒 + 最近门店"。

---

## 一、工具全景（33 个，按能力域 × 风险分级）

### 绿色区（纯查询，零成本，随便调）——15 个

| 工具 | 能力 | 输入依赖 | 关键返回 |
|------|------|---------|---------|
| now-time-info | 服务器时间 | 无 | 时间戳/日期/时区 |
| campaign-calendar | **当月营销活动日历** | 无（可选指定日期锚点） | 按日聚合的活动标题+文案+图片 |
| mall-points-products | **积分商城商品列表** | 无（可按类目筛选） | spuId/积分价/卖点/上下架时间/状态 |
| mall-product-detail | 商城商品详情 | spuId | SKU 规格（下单前置） |
| list-nutrition-foods | 餐品营养成分 | 无 | 热量/蛋白质/脂肪/钠等 |
| query-nearby-stores | 到店门店搜索 | 城市+关键词（或收藏） | storeCode/地址/距离/营业状态/预约时段 |
| delivery-query-addresses | 用户配送地址列表 | 无（登录态） | addressId |
| delivery-query-stores | 地址可配门店 | addressId | storeCode/beCode |
| query-meals | 门店餐品列表 | storeCode+beType | productCode/价格 |
| query-meal-detail | 餐品详情/特调 | storeCode+code | 组成/modification |
| query-promotions | 团餐促销规则 | 仅 beType=6 | 满减/满折原始规则 |
| query-meal-assistance | 团餐助餐服务 | 仅 beType=6 | gmServiceCode |
| query-my-account【实测】 | 积分账户详情 | 无 | 可用/累计/将过期积分 |
| query-my-coupons | 卡包优惠券 | 无 | 券列表（不做下单校验） |
| available-coupons | 可领取的券列表 | 无 | 麦麦省可领券 |
| query-lottery-info【实测】 | 抽奖活动信息 | 无 | 消耗规则/奖品池/drawDecision |
| query-my-prizes | 抽奖历史奖品 | 无 | 奖品+状态 |
| order-list / mall-order-list / query-order / query-survey-coupon | 历史订单/商城订单/订单详情/答卷 | orderId | 订单状态 |

### 黄色区（有轻微副作用，无金钱成本，调用前需说明）——2 个

| 工具 | 副作用 | 说明 |
|------|--------|------|
| auto-bind-coupons | 一键领取所有可领券 | 无成本，但写入用户账户 |
| delivery-create-address | 新增配送地址 | 写入用户账户数据 |

### 红色区（真实消耗金钱/积分，作品演示禁碰）——6 个

| 工具 | 消耗 | 备注 |
|------|------|------|
| calculate-price | 无（但为下单前置） | 算价本身免费，可安全演示 |
| create-order | 真实订单 | 需支付，禁止演示调用 |
| mall-create-order | 真实积分扣减 | 兑换即扣积分 |
| party-order-create | 真实积分/金钱 | 派对预约 |
| draw-lottery | 24 积分/次【实测确认】 | 有频次限制，必须用户确认后调用 |
| cancel-order | 撤销真实订单 | 非商城订单 |

### 强依赖链（调用顺序不可乱）

```
点餐链：query-nearby-stores → query-meals → query-meal-detail → calculate-price → create-order
商城链：mall-points-products → mall-product-detail → mall-create-order
派对链：mall-points-products → query-party-city → query-party-store → query-party-store-date → query-party-store-session → party-order-create
```

查询端作品只能安全用到各链的**前三环**，后两环属于红色区。

## 二、实测记录（2026-10-10 真实调用）

### 1. campaign-calendar【实测 ✅】

- 当月活动按日聚合返回，含进行中/往期/未来。
- **关键发现：10 月存在一条完整的 GD（PEACEMINUSONE）联名周边线，每周三一档**：
  - 10-08 联名复古棒球帽（任意消费 +39.9 元得，10:45 开售，APP 积分 10:40 抢先购）
  - 10-15 联名徽章第二弹（一套三枚，限量）
  - 10-22 限定主题丝巾（第三弹）
- 同时还有：韩式风味蘸酱上新、蓝莓爆爆珠麦旋风、麦金喜抽奖（10-10 积分霸王餐）、亲子读书会（含"开心乐园餐+随机玩具"）等。
- **历史不可回溯（实测记录）**：传 `specifiedDate=2026-09-15`，返回的仍是 10 月 7 日的活动内容，说明该接口只维护近期窗口，更早的历史无法取回 —— 故历史数据只能自行归档或人工补录。
- **含义：玩具/周边情报的"上新日历"数据源成立，且 10 月节奏恰好覆盖 1024 大赛期。**

### 2. mall-points-products【实测 ✅，发现数据坑】

- 按类目 `2>8,2`（周边+实物）查询返回：罗技键鼠套装（6666 积分）、Nike Book 2 麦当劳联名款（8888 积分）、酸黄瓜吧唧礼盒（800 积分）。
- 有"玩具"类目（catName）。
- **坑 1：返回的商品 status=2（上架）但 downTime 已过期**（如 8-21 到期的罗技套装），status 与时间窗不一致——作品必须自己按 downTime 过滤，不能信 status。
- **坑 2：无"每周玩具上新"的开心乐园餐专门类目**，积分商城与开心乐园餐玩具是两条线。
- **含义：积分价、兑换时间窗、限量规则可结构化获取 → "值不值得冲"的判断依据成立。**

### 3. query-nearby-stores【实测 ✅ + ❌】

- 福州"三坊七巷"正常返回 5 家店：storeCode、地址、距离、营业状态、预约时段（精确到早餐/午餐/下午茶/宵夜）。
- **❌ 硬边界：返回字段里没有任何玩具/周边库存信息。**"附近哪家店有货"在 MCP 能力上**不成立**。
- 屏南县关键词返回 600047 无门店（屏南县城无店或需换关键词）——门店搜索依赖城市+关键词，县域覆盖不全。
- **含义：方向定义必须降级——"哪家店有货"改为"开售时间提醒 + 最近可去门店 + 到店加价购规则解读"。**

### 4. query-my-account【实测 ✅】

- 可用 / 累计 / 已过期积分各若干（接口另有本月、下月将过期字段）。
- **含义：个人资产联动（"你的积分够换什么"）可以做，但测试账户积分不足，演示数据要用查询类工具展示结构而非真实兑换。**

### 5. query-lottery-info【实测 ✅】

- "周六麦金喜抽奖"进行中（活动排到 2030 年），24 积分/次，奖品池 27 项全公开（优惠券/会员卡/积分）。
- drawDecision 机制：服务端返回能否抽+实际消耗，禁止客户端自行推断。
- **含义：抽奖情报（奖品池/消耗/剩余次数）是纯读能力，可以做进作品；但触发抽奖是红色区。**

## 三、玩具情报站方向：能力映射对账表

原方向定义四问，逐一对标 MCP 能力：

| 方向定义 | MCP 支撑 | 结论 |
|---------|---------|------|
| 本月哪个玩具上新 | campaign-calendar（活动日历）+ mall-points-products（商城上下架时间） | ✅ **成立，双数据源可交叉** |
| 值不值得冲 | 积分价/加价购规则/限量信息/联名 IP 强度（文案内含） | ✅ 成立，但"值不值"的判断逻辑由作品自己定义 |
| 附近哪家店有货 | 门店接口**无库存字段** | ❌ **不成立，必须降级**（改为开售提醒+最近门店） |
| 积分商城能否兑换 | mall-points-products + query-my-account | ✅ 成立，且可做个人化（你的积分够不够） |

## 四、对作品设计的直接约束

1. **卖点重构**：原"附近哪家店有货"改为"**上新雷达**"——按周聚合周边发售节奏（GD 三连发这种连续档期是天然素材），配合个人积分资产给"冲/不冲"建议。
2. **数据可靠性**：积分商城 status 不可信，一律以 upTime/downTime 自行过滤；活动日历是纯文案（含 emoji 与图片 URL），需要解析清洗。
3. **演示安全**：全程只用绿色区工具即可跑通完整价值闭环；README/MCP_INTEGRATION.md 里把红色区工具列为"能力声明"而非"已调用"，避免审核争议（规则要求"真实使用 MCP 能力"，绿色区调用即满足）。
4. **合规红线**：活动文案含联名 IP（GD/Nike 等），转述时只陈述事实（发售时间/获取方式），不做品牌间对比、不贬损。
5. **账号风险**：作品若绑定个人账号演示（积分/卡包），截图必须脱敏 accountId。
